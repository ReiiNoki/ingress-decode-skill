## 1. 案例：Atbash 基础

**状态**：已验证；Atbash 变换与最终分段均可复现  
**来源**：2025-03-26 密码解密小课堂
**标题**：猩猩藏头不藏尾，Atbash翻转有玄机

### 1.1 题面

```
cbt33nzplgl878iw
```

### 1.2 解题链路

```
① 观察：混合字母+数字，长度16，字母部分看起来无意义
② 尝试 Atbash（字母前后对折，数字保持）：
   c→x, b→y, t→g, n→m, z→a, p→k, l→o, g→t, l→o, i→r, w→d
③ 结果：xyg33makoto878rd
④ 验证：makoto 是 Ingress 相关人名（关键词）
⑤ 格式检查：xyg + 33 + makoto + 878 + rd → 符合 Investigation Blog 格式
```

### 1.3 关键观察

- 数字部分（33, 878）直接保留，Atbash 只影响字母
- "makoto" 是有效 Ingress keyword
- 结果直接是 passcode，不需要多层

### 1.4 复盘

新手容易犯的错：把数字也做了 Atbash。记住——**数字在 Atbash 中通常保持不变**（除非明确提示）。

## 2. 案例：Reverse + ROT + Typo

**状态**：推测；Reverse 与 ROT 可复现，但最终补字和换字缺少充分题面支持  
**来源**：2025-05-04 密码解密小课堂
**标题**：猩猩为难玩家竟靠手滑键盘！

### 2.1 题面

```
yd623qfztu63bhw
```

### 2.2 解题链路

```
① Reverse:                   yd623qfztu63bhw → whb36utzfq326dy
② ROT-5（字母倒退5位）:       whb36utzfq326dy → rcw36poual326yt
③ 识别 typo:
   "poual" 不是已知词汇
   观察 QWERTY 键盘：p 附近是 o, u 附近是 r, a 附近是 t...
   推测本应是 "portal"，但猩猩手滑把 r 打成了 u，漏了 t
④ 手动修正:                  rcw36poual326yt → rcw36portal326yt
```

### 2.3 关键观察

- 这不是标准算法能解决的——需要**人工判断"手滑"**
- "poual" 接近 "portal" 但有两个错误：`r→u`（键盘上 u 在 r 旁边），漏了 `t`
- 解题路径是标准的（Reverse + Caesar），但最后一步需要**领域知识**

### 2.4 复盘

这类题的核心教训：**算法不是万能的**。如果中间结果接近一个已知 Ingress keyword 但拼写不对，考虑 typo 可能性。

## 3. 案例：盲文 + 点数运算

**状态**：未验证；盲文转写可复现，但来源文章的点数运算与算术矛盾  
**来源**：[2025-05-23 密码解密小课堂](https://bjres.net/2025/05/23/ingress-passcode-%e8%a7%a3%e5%af%86%e5%ae%9e%e6%88%98%ef%bc%9a%e7%9b%b2%e4%ba%ba%e6%91%b8%e8%b1%a1%ef%bc%9f%e4%b8%8d%ef%bc%8c%e6%98%af%e7%9b%b2%e6%96%87%e6%91%b8%e7%a0%81%ef%bc%81/)
**标题**：Ingress Passcode 解密实战：盲人摸象？不，是盲文摸码！

### 3.1 题面

```
⠃⠧⠑⠎⠊⠑⠊⠎⠉⠊⠑⠝⠉⠑⠞⠺⠑⠊⠋⠕⠁⠎
```

### 3.2 可复现部分

```
① 识别载体：六点式 Unicode 字符 → Braille（盲文）
② 盲文对照转拉丁字母：
   ⠃⠧⠑⠎⠊⠑⠊⠎⠉⠊⠑⠝⠉⠑⠞⠺⠑⠊⠋⠕⠁⠎
   ↓↓↓↓↓↓↓↓↓↓↓↓↓↓↓↓↓↓↓↓↓↓↓
   b v e s i e i s c i e n c e t w e i f o a s
   → BVESIEISCIENCETWEIFOAS

③ 识别 Ingress 标准 keyword: SCIENCE
   分段: BVE + SIEI + SCIENCE + TWEIFO + AS

④ 若按来源所述“每两个字符的亮点数相乘取个位”：
   S(3点) × I(2点) = 6
   E(2点) × I(2点) = 4
   → "64"

⑤ 同样计算 TWEIFO：
   T(4点) × W(4点) = 16 → 个位 6
   E(2点) × I(2点) = 4
   F(3点) × O(3点) = 9
   → "649"
```

### 3.3 来源勘误

来源文章把上述两段写成 `68` 和 `284`，并据此给出
`bve68science284as`。这些数字无法由文章描述的乘法规则推出：

- `2 × 2` 应为 4，不是 8。
- `4 × 4 = 16`，个位应为 6，不是 2。
- `3 × 3` 应为 9，不是 4。

因此这里只把盲文转写和 `SCIENCE` 分段视为已复现；来源给出的最终字符串保留作
历史记录，不作为已验证答案或可复用算法范例。

### 3.4 关键观察

- 盲文→字母的转换可以独立验证
- 自定义点数运算必须同时满足题面提示、算术和最终格式，不能因为结果“像 passcode”就跳过验证
- "SCIENCE" 是已知的 Ingress keyword 列表中的词

### 3.5 复盘

盲文题在 Ingress decode 中不算罕见，但“点数相乘”不是标准盲文规则。
先完成标准转写，再根据题面验证任何额外运算；来源文章也可能写错。

## 4. 案例：rect(4) 矩阵重排

**状态**：已验证；矩阵排列、读取方向与结果均可重复执行  
**来源**：2025-07-03 密码解密小课堂
**标题**：从一串乱码到 Ingress Passcode 的华丽变身

### 4.1 题面

```
37koati52azmwoq3
```

### 4.2 解题链路

```
① 观察：16个字符，可排 4×4 矩阵
② 排矩阵：
   3 7 k o
   a t i 5
   2 a z m
   w o q 3

③ 尝试多种读法：
   - 横读 → 原字符串（无效）
   - 竖读 → 3a2w7taokizqo5m3（无规律）
   - 竖倒读 → w2a3oat7qzik3m5o（无规律）
   - 旋转90° → w2a3oat7qzik3m5o（无规律）

④ 从左下角开始，从下往上逐行向右读：
   第4行: w o q 3 → woq3
   第3行: 2 a z m → 2azm
   第2行: a t i 5 → ati5
   第1行: 3 7 k o → 37ko

⑤ 拼合: woq32azmati537ko
```

### 4.3 关键观察

- 长度整齐（16=4²）是矩阵题的重要信号
- 需要尝试**所有可能的读法**
- 最终读法是"左下→右下"、"从下到上"，不是常规的"左上→右上"

### 4.4 复盘

矩阵题没有唯一正确答案法——需要系统性地尝试：横读、竖读、倒序、旋转、蛇形。如果一种读法得到规律性结果（字母+数字交替），就接近正确答案了。

## 5. 案例：键盘行 Morse

**状态**：未验证；来源输出与标准 Morse 及项目工具结果矛盾  
**来源**：[2025-06-29 密码解密小课堂](https://bjres.net/2025/06/29/ingress-%e8%a7%a3%e5%af%86%e8%af%be%e5%a0%82%ef%bc%9a%e7%a5%9e%e7%a7%98%e4%bb%a3%e7%a0%81%e7%ab%9f%e8%97%8f%e8%ba%ab%e9%94%ae%e7%9b%98%e6%91%a9%e6%96%af%e7%94%b5%e7%a0%81%ef%bc%9f/)
**标题**：Ingress 解密课堂：神秘代码竟藏身键盘摩斯电码？

### 5.1 题面

```
lfcree[
.'brua
'hc
'sq
[
tzlpeg.hdntqojjb
]ptoe.adwyr/lbyh
```

### 5.2 来源声称的解题链路

```
① 过滤非字母字符：
   lfcreebruahcsqtzlpeghdntqojjbptoeadwyrlbyh

② 键盘三行映射摩斯：
   顶行(qwertyuiop)→"―"，中行(asdfghjkl)→"·"，底行(zxcvbnm)→"/"
   → -- / .... / - / ..--- / -- / -..- / ---- / --.-. / ...-

③ 来源声称按标准 ITU Morse 解码：
   -- → M
   .... → H
   - → T
   ..--- → 2
   -- → M
   -..- → X
   ---- → 7
   --.-. → 3
   ...- → V

④ Ingress 式数字分段转换：
   2 → ..---  → 2
   7 → --...  → 7
   3 → ...--  → 3
   5 → .....  → 5
   7 → --...  → 7

⑤ 拼合: MHT27XM357TA
   → 格式: MHT + 27 + XM + 357 + TA
```

### 5.3 复现检查

该链路不能通过标准 Morse 或项目工具复现：

- `----` 不是标准数字 7；7 应为 `--...`。
- `--.-.` 不是标准数字 3；3 应为 `...--`。
- 按文章所述先删除全部非字母字符，再运行 `keyboard_row_to_morse()`，实际得到的分组
  解码为 `I O Z W ? 8 ? N`，不是 `M H T 2 M X 7 3 V`。
- 后续补出 `27`、`357` 和尾码 `TA` 的步骤没有可验证规则支撑。

### 5.4 复盘

键盘行映射 Morse 本身可以成立，但每一步输出仍必须符合标准码表。
所谓“容错”不能把任意非法码补成需要的数字；无法复现时应标记未验证，而不是继续拼答案。

## 6. 案例：多层组合

**状态**：教学示意；不是单一题目的答案，不适用可信度评级  
**来源**：2016-10 ~ 2017-02 旧系列教程
**标题**：典型多层链路

### 6.1 典型链路示例

```
链路 A:
原始密文 → Atbash → 结果可读但不是 passcode
         → 这是 Base64 字符串 → 解码 → 明文 → keyword 确认

链路 B:
原始密文（数字+字母混合）→ 排矩阵 → 竖读
         → 得到字母串 → ROT13 → 获得 keyword
         → 再从另一方向读数字部分 → 拼合 passcode

链路 C:
原始密文（图片）→ EXIF 中隐藏字符串
         → Base64 解码 → Morse 码
         → 解码 → keyword + 数字 → passcode
```

### 6.2 关键观察

- 多层解密时，**每层的输出都要判断"这是什么"**
- 常见的中间产物：Base64 字符串、Morse 码、ROT 后的字母串、keyword 提示
- **不要因为某一步得到可读英文就停下来**——它可能只是下一层的线索

### 6.3 复盘方法

每次解完多层题，用这个模板复盘：

```
第1层: [方法] → [输出] → 判断: 这是 [passcode/线索/下层密文]
第2层: [方法] → [输出] → 判断: 这是 ...
...
最终: 拼合 → passcode
漏看的线索: [写下来]
```

## 7. 学习建议

1. **先看题面，别看答案** — 自己列一份线索清单
2. **用 `workflow.md` 的实战记录模板** — 系统化你的思路
3. **对比参考答案** — 标出自己漏了什么
4. **复述解题链路** — 能讲清楚每一步为什么这么做
5. **用 `scripts/quick_decode.py` 验证** — 跑 `scan_all()` 快速试基础操作
