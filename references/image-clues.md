# 图片与外部线索检查指南

图片题的目标不是“把所有隐写工具跑一遍”，而是按成本和题面证据逐层检查，并保留每一步可复现记录。

## 1. 保存原始证据

1. 优先取得原始文件，不用社交平台截图替代；截图可能丢失元数据、动画帧、透明通道和原始尺寸。
2. 记录来源 URL、标题、发布时间、正文、图片顺序、文件名、扩展名和页面中的 `alt` 文本。
3. 保存原文件副本，后续旋转、裁切、调色或格式转换都在副本上进行。
4. 记录像素尺寸、文件大小、实际格式和哈希；扩展名与文件签名不一致本身可能是线索。

如果只能获得截图，明确标记“非原始文件”，不要对缺失的 EXIF 或透明通道作结论。

## 2. 快速目视检查

按以下顺序做低成本检查：

1. 原尺寸、放大、缩小各看一次；缩小后出现的整体轮廓可能比像素细节更重要。
2. 检查边缘、角落、负空间、裁切区域、重复图案、异常对齐和与背景接近的文字。
3. 尝试 90°、180°、270° 旋转和水平/垂直镜像，但记录是哪种变换产生结果。
4. 检查亮度、对比度和反相；不要只凭肉眼调到“像某个字”为止。
5. 数对象、颜色、行列、间距和重复次数，判断是否对应字母表、Morse、二进制或矩阵分组。

输出应描述观察事实，例如“共有 24 个色块，按 6×4 排列”，而不是直接写“这一定是 Base64”。

## 3. 文字与机器码

### 3.1 OCR

- 对原图、放大图、灰度图和高对比度图分别尝试 OCR。
- 保留 OCR 原始输出，并人工核对易混字符：`0/O`、`1/I/l`、`5/S`、`8/B`、`-/_`。
- 对等宽字符、手写体或 Glyph 不要只信单次 OCR；逐字符确认或标记歧义集合。

### 3.2 二维码与条形码

- 先在原始方向读取，再尝试旋转、裁切、反相和提高对比度。
- 读取失败时检查码是否被拆成多张图、缺少静区、颜色反转或分布在多个动画帧。
- 解出的 URL 或文本只是下一层输入；继续记录跳转目标和页面内容，不把能打开链接视作最终答案。

### 3.3 可见字符串

将图片中的文字、文件名和 `alt` 文本分别保存，不要过早拼接。之后按
`cipher-patterns.md` 判断 Base64、Hex、Morse、键盘、矩阵或其他编码。

## 4. 文件结构与元数据

在有原始文件时检查：

- EXIF/XMP/IPTC：作者、时间、GPS、注释、软件、方向标记。
- PNG 文本块、调色板、透明度和附加数据。
- GIF/WebP/APNG 的帧数、帧延迟、帧差异和循环顺序。
- 文件尾部是否存在附加文本或第二个文件签名。
- 实际 MIME/文件签名是否与扩展名一致。

可使用现有环境中的 `exiftool`、ImageMagick `identify -verbose` 或同类只读工具；工具不可用时，
记录未检查项，不要声称“没有元数据”。元数据必须与题面相关才算证据，普通相机信息可能只是噪声。

## 5. 颜色、通道与多帧内容

### 5.1 颜色

1. 记录精确 RGB/HEX 值和出现顺序，不只写“红色”“蓝色”。
2. 检查每个通道、灰度、alpha 和调色板索引是否形成不同信息。
3. 题面提示 opposite、inverse、complement 时，再计算反色或互补色。
4. 色值像 ASCII、坐标或字母编号时，按标准范围验证；不要随意舍弃高位或补零。

### 5.2 动画和多图

- 逐帧查看新增、消失和移动的区域。
- 比较相邻帧差异、播放顺序和帧延迟；时间长度可能编码点横或数字。
- 多张等尺寸图片可能需要叠加、相减、异或或按页面顺序排列，但必须有结构或题面提示支持。

## 6. 地图与外部页面

### 6.1 地图与坐标

- 确认纬度/经度顺序、正负号、度分秒与十进制度格式。
- 记录坐标指向的 Portal、地标、城市、道路或图形，不只保存地图截图。
- 检查 Portal 名称、地标英文名、路线、Link/Field 形状和数量是否能解释 keyword 或数字段。

### 6.2 页面与 HTML

- 检查图片 URL、文件名、`alt`、标题、链接 slug、HTML 注释和附近文本。
- 页面脚本或样式只在题面确有异常时深入检查；普通框架代码通常不是线索。
- 外部搜索得到的人名、地点或引文必须能回扣题面，不能仅因它能拼出 passcode 就采用。

## 7. 验证与记录

图片题至少记录以下内容：

```text
原始文件/来源：
是否为原图：
尺寸、格式、文件大小：
页面文字、文件名、alt：
目视观察：
OCR/二维码输出：
元数据与文件结构：
颜色、通道、帧：
地图或外部搜索：
使用的变换及参数：
候选结果：
仍未检查或无法取得的信息：
可信度：
```

最终按 `workflow.md` 的可信度等级报告。图片经过平台压缩、缺少原文件或 OCR 存在歧义时，
应降低可信度并保留候选字符，而不是静默修正成期望答案。
